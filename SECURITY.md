# Security Policy

## Supported versions

Security fixes target the latest public plugin release and the current `main` branch.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities, secrets, credential leaks, private logs, or exploitable workflow problems.

Report sensitive issues by email to:

```text
albertnajjar@outlook.com
```

Include:

- affected version or commit
- operating system and Codex/runtime context
- steps to reproduce
- impact
- any safe logs, output tails, or proof-of-concept notes

Please remove secrets, tokens, private repository names, customer data, and unrelated local paths before sending logs.

## What to expect

The maintainer will triage the report, ask for missing reproduction detail if needed, and coordinate a fix or mitigation. Public disclosure should wait until there is a reasonable patch or workaround.

## Non-security bugs

For ordinary crashes, stale cache behavior, confusing docs, dashboard issues, benchmark-contract problems, or UX paper cuts, use the public issue templates instead.
